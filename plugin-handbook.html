Handbook · Plugin Runtime

ModelSphere 插件手册

前半部分是使用者在装、看、升级、卸载插件时要知道的东西；后半部分写给要接入的团队，最后用北极星走一遍完整接入。

先跑通 
modelsphere plugin validate ./helm/polaris
modelsphere plugin package ./helm/polaris -d ./dist
modelsphere plugin install ./dist/polaris-1.0.0.tgz
modelsphere plugin registration ./dist/polaris-1.0.0.tgz \
  | kubectl apply -f -
modelsphere plugin list

命令默认读本机 kubeconfig 与 ModelSphere 配置；Console release 与命名空间可从配置文件取，也可用 --console-release、--console-namespace 指定。

I

使用者

你只操作两个对象：Helm release 和 Plugin CR。理解它们的分工，后面所有操作都能自己推出来。

01

四件东西

装一个插件会先后出现四个东西。只有第三个是你日常要改的。

东西是什么你管不管
插件包一个 .tgz，里面是 Chart、plugin.yaml 和编译好的前端你从插件仓库拿到
Helm release真正跑起来的 Deployment、Service、PVC、ReverseProxy装一次，升级时再动
Plugin CR一条集群范围内的声明，决定 Console 加不加载这个插件日常开关、升级版本都改它
Console观察者：读 CR、读 release、发布前端文件和接口不用动，重启后自己恢复
一句话规则 release 决定插件跑不跑，CR 决定插件看不看得见。装完不显示，先查 CR；CR 是 Installed 但页面白屏，才去看插件自己的前端。
02

环境与配置

需要 helm、kubectl、能连到目标集群的网络，以及 modelsphere 可执行文件。CLI 自己不做认证，它把 --kubeconfig 和 --context 原样传给 helm 和 kubectl。

把默认值写进配置文件，命令就不用每次带参数。路径是 $(os.UserConfigDir)/modelsphere/config.yaml，macOS 上是：

# ~/Library/Application Support/modelsphere/config.yaml
kubeconfig: /Users/you/.kube/kubeconfig-cpu16-admin.yaml
context: kubernetes-admin@kubernetes
console:
  release: modelsphere-console
  namespace: console-system

也可以用环境变量 MODELSPHERE_CONFIG 指到别的文件，或用全局参数临时覆盖：

参数作用
--kubeconfig · --context传给 helm 与 kubectl，也用于 CLI 自己的读取
--config指定配置文件，替代默认路径
--timeout单条外部命令的超时，默认 5 分钟
-v · --verbosity0–10。卡住时用 -v 2 看实际执行的命令，-v 4 看子进程输出（敏感值会打码）
--helm · --kubectl指定可执行文件路径，用于多版本并存

连通性用一条只读命令确认：

modelsphere plugin list
03

命令速查

命令作用副作用
plugin validate <路径>检查 Chart、plugin.yaml、前端入口是否自洽无，不连集群
plugin package <目录> -d <输出目录>先校验再 helm package只写输出目录，不改版本
plugin install <包>解析能力、生成 values、helm upgrade --install --atomic --wait建或改名为插件名的 release，不建 CR
plugin registration <包>打印一条 Plugin CR 到 stdout无，需要你自己 apply
plugin list列出已注册插件的身份、版本、release 与状态无
plugin uninstall [group/name]删 CR，再 helm uninstall需要 CR 存在；非交互要加 --yes

install 常用参数：--plugin-namespace（默认跟随 Console 命名空间）、-f/--values（可重复）、--wait（默认开启）。

04

生命周期：装、注册、升级、停用

安装不注册

plugin install 结束时会明确打印：

Installed runtime: modelsphere.dev/polaris 1.0.0
Registration is separate: create a Plugin CR to load it in Console.

这不是漏了一步，是故意的。注册权可以单独授予：平台装运行时，业务方或 GitOps 决定什么时候对外可见。所以 plugin list 为空时，第一件事是确认 CR 是否存在，而不是怀疑安装失败。

注册：先看，再 apply

modelsphere plugin registration ./dist/polaris-1.0.0.tgz > polaris.yaml
kubectl apply -f polaris.yaml
modelsphere plugin list

生成的 CR 长这样。metadata.name 是 group 与 name 用 -- 拼起来的资源名，spec.chart 只用来定位已安装的 release，写它不会触发安装。

apiVersion: modelsphere.dev/v1alpha1
kind: Plugin
metadata:
  name: modelsphere.dev--polaris
spec:
  type: helm
  scope: platform
  enabled: true
  version: 1.0.0
  chart:
    name: polaris
    namespace: console-system
    releaseName: polaris

升级

改 Chart.yaml 的 version，重新打包，对同一个包再执行一次 install。release 名默认等于 plugin.yaml 的 name，所以它会原地升级。

如果 CR 里写了 spec.version，升级后要把它改成新版本。Console 会核对 release 里的 Chart 版本，对不上就报 installed Chart does not match registration 并停在 Degraded。不想每次改两处，就别在 CR 里写 version：这一项是可选的，不写就不校验。

停用与卸载

# 停用：从界面移除，release 与权限都保留
kubectl patch plugins.modelsphere.dev modelsphere.dev--polaris \
  --type merge -p '{"spec":{"enabled":false}}'

或者一条命令做成卸载：删 CR 让插件立刻从界面消失，再 helm uninstall 清掉运行资源。

modelsphere plugin uninstall modelsphere.dev/polaris --yes
顺序不能反 先删 release 会留下一条指向空 release 的 CR，Console 会持续重试读取并报 Degraded。CLI 因此把「CR 存在」作为卸载前置条件，也要求先删 CR。已经打开的页面需要刷新才会卸掉已执行的 JS，热卸载不在当前范围内。
05

谁能看见，谁能调用

前端和后端是两套独立的授权，配置的时候要分别想。

层面控制什么在哪里配置
导航菜单和页面是否出现插件自己在组件里用 SDK 导出的 usePermissions() 判断；菜单的 authKey 会随菜单注册，宿主当前不按它过滤
接口/api/<插件>/* 能不能调IAM 角色在 backends 资源上按插件名授权
写操作能否调用会改数据的接口另外授予 <插件名>.write

接口鉴权按 HTTP 方法映射成 RBAC 动词：GET/HEAD/OPTIONS 对应 get，POST 对应 create，PUT/PATCH 对应 update，DELETE 对应 delete。调用者身份以 X-Remote-User 和 X-Remote-Group 透传给插件后端。

前端文件是公开的 除 /api/ 和 /oauth/，Console 的静态路径不需要登录。插件 JS 被当作可信代码直接下发，所以包里不能有密钥、令牌或内部地址。插件需要凭据时，通过 consumes 拿到 Secret 的引用，让后端去读。
06

出问题先看哪里

现象先确认
plugin list 是空的还没注册。install 只建 release，列表读的是 CR
Console 一直 503CRD 是否已安装；informer 首次同步是否完成
CR 停在 Degradedstatus.conditions 或 status.message：release 不存在、Chart 版本不匹配、Console 读不到 release Secret
列表里有，界面没菜单浏览器控制台：入口是否抛错导致整次注册回滚；/plugins/index.json 里是否有该条目
菜单在，点开白屏浏览器控制台。入口抛错会被回滚，整块注册不生效
前端文件 404frontend/entry 是否真的在包里；文件名是否含 ? # % 等非法字符
接口 403角色在 backends 上是否对插件名授予了对应动词
接口 404ReverseProxy 的路径是否以 /api/ 开头并以 / 结尾；是否命中已注册路由
提示宿主不支持 SDKSDK 主版本与宿主不一致，升级插件依赖到 1.x

Console 的 /readyz 在首次同步完成前返回 503，这是设计行为，不是崩溃。

II

接入方

一个插件 = 一个 Chart + 一个前端入口 +（可选）一个后端。下面是按这个顺序展开的接入步骤。

07

先做三个决定

决定影响说明
身份CR 资源名、插件 id、URL 段group + name。反向域名 + 小写 kebab-case
前端入口能不能出现在侧边栏必须有 frontend/<entry>；至少注册一个菜单和一个组件
后端要不要自己的接口要，就加一条 /api/<name>/ 的 ReverseProxy
宿主增强是否往宿主页面加内容数据、可见性、呈现、动作四类扩展，可选
平台能力安装时是否要注入平台配置镜像拉取密钥、推理命名空间、模型网关，用 consumes
08

plugin.yaml

这个文件只描述「我是谁、入口在哪、我需要什么」。菜单、后端地址都不写在这里。

apiVersion: v1
name: polaris                 # 插件 id，必须与 createPlugin 的 name 一致
group: modelsphere.dev
version: 1.0.0                # 必须等于 Chart.yaml 的 version
displayName: 北极星
description: 实验、分桶与推理服务的关系管理。
frontend:
  type: component
  runtime: remote
  entry: index.umd.js         # 相对 Chart 内的 frontend/
consumes:
  - capability: swiss.modelsphere.dev/gateway
    version: v1
字段必填约束
apiVersion是只接受 v1
name是小写 kebab-case；等于前端 createPlugin 的 name，也是 /plugins/index.json 里的 id
group是反向域名；与 name 合成 CR 资源名
version是严格 SemVer，且与 Chart version 完全一致
frontend.entry是文件必须真实存在，否则打包和安装都会失败
provides / consumes否<group>/<name> 加版本
严格解析 CLI 和 Console 都按已知字段严格解析。多写一个不认识的键（比如 menus、backend、frontend.service）会直接报错：CLI 在 validate 时失败，Console 则让 CR 进入 Degraded。菜单在 bundle 里注册，后端在 ReverseProxy 里声明。
09

前端：一个入口，几行注册

依赖只有 @modelsphere/plugin-sdk。React、react-router、react-query 和 UI 组件都由宿主提供单实例，插件不要打包自己的副本。构建配置交给 SDK 的预设：

// tsup.config.ts
import { definePluginConfig } from "@modelsphere/plugin-sdk/build";

export default definePluginConfig({
  name: "polaris",
  entry: "frontend/src/runtime.tsx",
  outDir: "frontend/dist",
  cssSource: "frontend/src",
});

入口文件调用一次 createPlugin：

import { createPlugin } from "@modelsphere/plugin-sdk";
import { PolarisList } from "./pages/PolarisList";
import { ExperimentDetail } from "./pages/ExperimentDetail";

declare const __PLUGIN_VERSION__: string;

createPlugin({
  name: "polaris",
  version: __PLUGIN_VERSION__,
  displayName: "北极星",
  icon: "flask-conical",
  menus: [{ name: "polaris", path: "/polaris", scope: "platform", title: "北极星" }],
  components: { PolarisRoot: PolarisList },
  routes: {
    "/polaris": PolarisList,
    "experiments/[id]": ExperimentDetail,
  },
});
约定细节
版本__PLUGIN_VERSION__ 由构建从 Chart.yaml 注入，不要手写版本号
菜单第一个非隐藏菜单决定模块标题和侧边栏入口，scope 必填
路由只接受字面段、[param]（转成 :param）和 [...rest]（转成 *）；其它写法在注册时抛 Unsupported SDK route
图标当前只接受 boxes、flask-conical、puzzle，其它值会让整个入口加载失败
样式只提交候选类清单，宿主把所有插件的类合并编译成一张样式表；插件不自带 Tailwind，也不覆盖主题
失败会整体回滚 入口里的任何一步抛错（版本不匹配、未知图标、组件没注册、扩展 id 重复），Console 会把这次注册全部撤销，菜单不出现。看浏览器控制台能看到具体原因。
10

后端：一条 ReverseProxy

插件后端不写在 Console 配置里，而是作为插件包的一部分，在 Chart 里声明。Console 从已安装的 release 清单里找 ReverseProxy：

apiVersion: iam.theriseunion.io/v1alpha1
kind: ReverseProxy
metadata:
  name: polaris
  namespace: {{ .Release.Namespace }}
spec:
  matcher:
    method: "*"
    path: /api/polaris/*
  upstream:
    scheme: http
    host: polaris.{{ .Release.Namespace }}.svc
    port: 8080
  directives:
    authProxy: true

Console 会拒绝不合规的规则：路径必须以 /api/ 开头、以 / 结尾，authProxy 必须为 true，上游只接受 http/https 和合法端口。一条不合规的规则会让 CR 进入 Degraded，而不是挂一个不受保护的路径。

插件前端通过宿主给的 api 客户端调用自己的接口，路径写绝对的同源路径：

const { data } = await plugin.api.get("/api/polaris/experiments", {
  params: { limit: 50 },
});

客户端会自动带上会话令牌和 Cookie。失败时抛出 ApiError（带状态码），由页面自己决定提示还是引导重新登录。不要用 fetch 裸调，也不要拼绝对域名：SDK 只接受同源路径。

11

要平台能力就声明 consumes

插件不应该知道宿主怎么配镜像拉取密钥或模型网关。在 plugin.yaml 里写需要什么，安装时由 CLI 解析出值，写进一份临时 values 文件后删除。插件拿到的是 Secret 引用，不是值。

内置能力给了什么
modelsphere.dev/platformimagePullSecrets（同命名空间）、inferenceNamespaces
modelsphere.dev/swissendpoint、apiKeyRef、apiKeyKey

值写进 consumed.<provider>.<key>，Chart 里用对应的键读。多个提供方满足同一个能力时必须写 from 指定，否则安装直接失败，避免静默连错。

12

从打包到验收

构建前端并放进 Chart

先把 bundle 构建到 frontend/dist，再复制到 Chart 的 frontend/。CLI 会检查 frontend/<entry> 是否存在，缺了直接失败：

pnpm -C frontend build
cp -R frontend/dist helm/polaris/frontend

校验

modelsphere plugin validate ./helm/polaris

打包

modelsphere plugin package ./helm/polaris -d ./dist

产物名是 <Chart name>-<version>.tgz。

安装运行时

modelsphere plugin install ./dist/polaris-1.0.0.tgz

加 -v 2 可以看到解析出的能力和实际执行的 helm 命令。

注册并确认

modelsphere plugin registration ./dist/polaris-1.0.0.tgz | kubectl apply -f -
modelsphere plugin list

页面验收

刷新 Console，菜单出现；打开页面无控制台报错；调一次接口返回 200；用无权限账号确认菜单消失、接口 403。

III

北极星

北极星是正在接入的插件：实验、分桶、价格与 Metrics，外加往推理服务列表和详情里补关系信息。下面是它落到当前合同上的样子。

14

先对齐：旧清单要删掉一半

北极星的 plugin.yaml 是在旧合同下写的，带了自己的前端服务地址、后端地址、菜单和 requires。这些字段在现在的合同里各有归属，不能原样保留。

现在写的归到哪里
frontend.service（独立前端服务地址）删掉。前端文件由 Chart 的 frontend/ 直接发布，不再需要单独的服务和镜像
backend（地址与 prefix）删掉。改成 Chart 里的 ReverseProxy，路径 /api/polaris/*
menus删掉。菜单在 bundle 的 createPlugin 里注册
requires换成 consumes，只用于安装期注入平台能力
—补上 apiVersion: v1 与 frontend 三件套（type、runtime、entry）
删不干净会立刻失败 严格解析不认识旧字段。留着 backend 或 frontend.service，Console 会在加载时让 CR 进入 Degraded，报错就是字段解析失败。
15

北极星的清单与入口

apiVersion: v1
name: polaris
group: modelsphere.dev
version: 1.0.0
displayName: 北极星
description: 实验、分桶与推理服务的关系管理。
frontend:
  type: component
  runtime: remote
  entry: index.umd.js
consumes:
  - capability: swiss.modelsphere.dev/gateway
    version: v1

入口把五个页面收进一个菜单，再用路由拆开：

createPlugin({
  name: "polaris",
  version: __PLUGIN_VERSION__,
  displayName: "北极星",
  icon: "flask-conical",
  menus: [{
    name: "polaris",
    path: "/polaris",
    scope: "platform",
    title: "北极星",
    authKey: "polaris.view",
  }],
  components: {
    PolarisRoot: PolarisList,
    BucketCell,
    ServiceRelationship,
  },
  routes: {
    "/polaris": PolarisList,
    new: ExperimentCreate,
    pricing: Pricing,
    metrics: Metrics,
    "experiments/[id]": ExperimentDetail,
  },
});

authKey 目前只是随菜单注册的声明，宿主不会据此过滤；要真正按权限隐藏菜单内容或路由，在组件里调用 SDK 导出的 usePermissions()。侧边栏图标只能用 flask-conical、boxes、puzzle 三者之一。

16

北极星往推理服务里加东西

北极星要在推理列表加一列归属信息，在详情头部加关系区块，并在被实验引用时禁用升级和卸载。这对应四类扩展，各自独立注册。

// 1. 数据：每个资源单独取一次
dataExtensions: [{
  id: "polaris.relationship",
  resourceType: "inference-service",
  load: async ({ resource }) => fetchRelationship(resource),
}],

// 2. 可见性：只拿得到资源与数据，拿不到权限对象
visibilityExtensions: [{
  id: "polaris.relationship.visible",
  resourceType: "inference-service",
  placement: "resource.header",
  evaluate: ({ data }) => Boolean(data["polaris.relationship"]),
}],

// 3. 呈现：行内与详情头部
presentationExtensions: [
  { id: "polaris.row", resourceType: "inference-service",
    placement: "collection.row", key: "polaris.relationship",
    component: "ServiceRelationship" },
  { id: "polaris.header", resourceType: "inference-service",
    placement: "resource.header", key: "polaris.relationship",
    component: "ServiceRelationship" },
],

// 4. 动作：返回字符串就是拒绝原因
actionExtensions: [{
  id: "polaris.block-write",
  resourceType: "inference-service",
  action: "uninstall",
  evaluate: ({ resource }) =>
    isReferencedByExperiment(resource) ? "被实验引用，先停止实验" : false,
}],
当前宿主的真实行为对北极星的影响
只渲染了个接入点：inference-service 的 collection.row 与 resource.header其它 placement 会注册成功但不会显示，不要按提案里的列/Tab 直接排期
数据扩展每行调用一次，缓存 30 秒列表页 50 行就是 50 次请求。后端要提供批量接口，或在前端按页合并
可见性扩展拿不到权限对象不能写 permissions.has("polaris.view")；权限交给菜单 authKey，可见性只看数据够不够
动作策略里的 data 是空对象拒绝原因必须从 resource 或后端权威结果得出，不能用数据扩展的返回值
动作名是 upgrade、uninstall、rollback、slo按这几个名字注册，写错名字不会生效，也不会报错
权威数据 决定宿主能不能卸载的数据必须来自插件后端或宿主认可的策略接口。用前端算出来的徽标状态去阻止写操作，等于让一个可失败、可过期的查询决定权限。
17

上线步骤与验收

准备 Chart

Chart 里保留 Deployment、Service、ReverseProxy；把旧的独立前端服务相关模板和 values 项删掉。构建产物复制到 frontend/。

校验并打包

modelsphere plugin validate ./helm/polaris
modelsphere plugin package ./helm/polaris -d ./dist

安装到 Console 命名空间

modelsphere plugin install ./dist/polaris-1.0.0.tgz \
  --plugin-namespace console-system -v 2

关注输出里的能力解析结果，确认网关地址来自 swiss 提供方。

注册

modelsphere plugin registration ./dist/polaris-1.0.0.tgz | kubectl apply -f -
kubectl get plugins.modelsphere.dev modelsphere.dev--polaris \
  -o jsonpath='{.status.phase}{"\n"}{.status.message}{"\n"}'

期望 Installed。Degraded 时先看 message，再看 status.conditions。

页面与接口验收

菜单出现并能进入五个页面；推理列表出现关系列；被实验引用的服务上「卸载」呈禁用并显示原因；curl /api/polaris/experiments 带登录态返回 200；无 backends 权限的账号返回 403。

回滚

kubectl delete plugins.modelsphere.dev modelsphere.dev--polaris
modelsphere plugin uninstall modelsphere.dev/polaris --yes

先删 CR 让界面立即回到接入前，再卸运行时。

新增插件不用改 Console 北极星接入完成后，Console 侧唯一的变化是注册表里多一条、合并样式表里多一批候选类。以后再接别的插件，路径完全一样。

命令与行为以 cmd/modelsphere、internal/plugincli、internal/pluginregistry 的当前实现为准；前端约定见 web/packages/plugin-sdk。架构层面的说明见《ModelSphere 可插拔架构》。
