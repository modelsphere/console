Plugin / CLI 交互与数据流

安装插件，只输入插件

Console 是宿主，插件包是输入。借鉴 Global，插件用 group/name 唯一定位；宿主目标、当前注册表和已有 Helm 状态由 CLI 自动发现和读取，不能要求用户把宿主内部数据重新输入一遍。

日常安装命令
modelsphere plugin install ./canaryd-0.3.0.tgz

用户只提供插件包路径。只有当前 context 找不到 Console，或发现多个 Console 无法判断时，CLI 才请求额外选择。

为后续融合保留同一条路径

插件包沿用 Global 的身份和元数据；ModelSphere 只补宿主发现、Console 注册和 CLI 生命周期，不再创造第二套插件包语义。

Discovery

先列出插件，再决定卸载谁

用户不需要记住 release 名称。CLI 从宿主的 Plugin 注册表读取稳定身份，再关联 Helm release；列表同时给出可用于卸载的完整标识。

modelsphere · list
$ modelsphere plugin list

发现 Console ..................................... modelsphere-console / console-system
读取 Plugin 注册表和 Helm release ................. ok

IDENTITY                 VERSION   KIND    RELEASE   STATUS
modelsphere.dev/canary   0.4.0     Plugin  canary    Ready
modelsphere.dev/metrics  1.2.1     Plugin  metrics   Ready

卸载时可使用 IDENTITY，也可以省略参数进入选择。
卸载目标不是 release 名称。日常交互使用列表中的 group/name；Helm release 只是宿主运行时实现，可能与插件身份不同，不应该成为用户必须记忆的主标识。

Global contract

Global 的 kind、group 和身份如何分层

Global 是后续融合的插件包兼容基线。这里必须按字段所在的对象区分，不能把三个不同层次都叫作“插件 kind”。

层次字段含义与 Console 映射
插件包 plugin.yamlgroup/name、version、apiVersionGlobal 的稳定身份是 group/name；version 是插件能力版本；apiVersion 只表示元数据契约版本。Global 的 plugin.yaml 不声明 Kubernetes kind。
宿主 Plugin CRapiVersion: plugin.rise.io/v1alpha1
kind: Plugin		这是 Kubernetes 宿主对象的类型。Console 可以用自己的宿主 API 版本和 kind: Plugin 表示安装记录，但对象身份仍必须来自插件包的 group/name。
包目录来源origin.kindImageSeed、CLIUpload、Unknown 表示包如何进入目录，与插件类型、Kubernetes kind 和插件身份都无关。
Console 适配结论。本例插件身份是 modelsphere.dev/canary，其中 modelsphere.dev 是 group；Console 的安装记录可以有 kind: Plugin，但 Plugin 是宿主对象类型，不是 group。CLI 列表和卸载使用 group/name，不能用单独的 name 或 Helm release 代替。

面向融合的兼容边界

共用插件包合同沿用 Global 的 plugin.yaml：name、group、apiVersion、version，以及前端入口、后端声明、依赖和部署 Chart。两边都从这里读取插件身份与版本。
ModelSphere 宿主适配只负责把共用包接入 Console：发现 Console、生成或更新宿主的 kind: Plugin 安装记录、注册前端资源、配置后端代理和校验运行状态。
Global 宿主适配继续使用 Global 的 Plugin CR、目录 API、权限和 SDK。它和 ModelSphere 共享插件包身份，不要求两个宿主共享同一套安装记录。
CLI 融合点包校验、打包、列表和身份解析使用同一套 group/name/version；只有“目标宿主发现、注册方式和状态验证”由宿主适配器决定。
Data flow

安装背后的数据流

CLI 不是把一堆参数转发给 Helm，而是先把用户输入、插件包数据和宿主数据合成一个安装计划。

1

用户输入

插件包路径。可选确认、context 覆盖或目标选择。

2

读取插件包

manifest、Chart、Service 声明、菜单和镜像默认值。

3

发现宿主

读取 kubeconfig，定位 Console release、namespace 和 chart。

4

合成计划

合并现有 Console 注册、插件 release 状态和插件声明。

5

执行并验证

部署插件、更新 Console、检查 Services 和 plugin index。

Source of truth

每一类数据从哪里来

用户只提供

  • 插件包路径
  • 安装或卸载确认
  • 存在多个 Console 时的目标选择
  • 需要环境差异时的 profile 覆盖

插件包提供

  • Global 兼容的 group/name、插件版本和元数据契约版本
  • 前端入口、菜单、路由和后端 prefix
  • 前端/后端 Service 声明
  • Chart 默认值与已发布的镜像引用

宿主自动提供

  • 当前 Kubernetes context
  • Console release、namespace、chart
  • 当前 Console plugins/backends 配置
  • 已有插件 release 的 values 和状态

运行后验证

  • 插件声明的前端和后端 Service
  • Pod readiness 和 Helm release 状态
  • Console /plugins/index.json
  • 入口资源和后端代理的 HTTP 响应
数据来源CLI 处理
Console release当前 context 自动发现只有发现 0 个或多个候选且无法判断时才询问用户。
已安装插件列表Console Plugin 注册表 + Helm release 状态展示 group/name、插件版本、宿主 kind、release 和状态；卸载选择以此为准。
当前 plugins宿主 Plugin 资源 / Console registry以宿主当前值为基线，按 Global 的 group/name 做新增或替换。
插件镜像插件包 Chart defaults / package lock用户不填写 tag；CI 在打包时固定发布镜像引用。
插件 release values已有 release 或插件包默认值升级时自动复用已有 values；首次安装使用包内默认值。
Console URL宿主 Service / 当前访问端点用于验证 plugin index，不作为安装前的必填参数。
Why current flags are wrong

当前命令为什么暴露了不必要的信息

当前实现：用户被迫拼装宿主状态

plugin install package \
  --console-release modelsphere-console \
  --console-namespace console-system \
  --console-chart ./helm/console \
  --values canary-values.yaml \
  --values image-values.yaml

目标交互：用户只表达业务意图

plugin install ./canaryd-0.3.0.tgz

// 多宿主时才需要：
plugin install package \
  --console modelsphere-console
image-values 不是用户输入。它暴露出来，是因为当前插件包没有把部署所需的镜像引用和默认值封装完整。应由 CI 在 package 阶段固定镜像引用，或由宿主的环境 profile 提供；不能要求用户手工编辑第二个 YAML。
CLI contract

建议的命令契约

日常安装modelsphere plugin install <package>。自动发现唯一 Console，使用包内 defaults 和已有 release 状态。
插件列表modelsphere plugin list。列出当前宿主可管理的 group/name、版本、宿主 kind、release 和状态。
日常卸载modelsphere plugin uninstall 进入选择；modelsphere plugin uninstall <group/name> 用于脚本。从当前宿主注册表确认插件，不要求 Console 参数。
预览计划modelsphere plugin install <package> --plan。只读取数据并展示目标、合并结果和待执行动作。
自动化覆盖--context、--console、--profile 只用于多集群、多宿主或 CI，不进入普通操作路径。

这个页面描述的是目标 CLI 交互和数据流，不是新增一个插件管理页面。下一步应先调整 CLI 的宿主发现、包默认值和 plan 输出，再决定具体参数名。
