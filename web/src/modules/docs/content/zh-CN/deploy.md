# 部署模型

模型部署由集群里的 swiss（swissd）执行：每次部署、升级、回滚都会先生成**部署计划**、预览变更，确认后才真正执行。

## 首次使用：初始化站点

如果 swissd 还没有站点配置，进入模型服务时会看到 **初始化站点** 页。填写这个集群的基本情况后保存：

- 模型目录：可部署的模型从哪里来
- chart 仓库与镜像仓库
- 模型路径模板：权重在节点上的存放位置

之后可以随时在 [站点配置](/inferences/site-profile) 修改，支持表单和 YAML 两种编辑方式，保存前服务端会先校验。

## 1. 在模型库里选模型

打开 [模型库](/inferences/catalog)：

- 用搜索框和筛选条件（系列、引擎、硬件、标签）缩小范围；勾选「仅调优过」只看有调优变体的模型。
- 点模型卡片进入详情。**变体**页列出这个模型的各种部署形态（GPU 型号、卡数、引擎），每个变体会显示「N 个节点可用」——这是按当前集群空闲 GPU 计算的适配结果。
- 在合适的变体上点 **部署**。

## 2. 填写部署表单

| 分区 | 主要字段 | 说明 |
|---|---|---|
| 基本信息 | 服务名、命名空间 | 服务名同时用作 helm release、路由、伸缩器和 SLO 的名字；只能用小写字母、数字和 `-`，最多 53 个字符。**部署后不能修改** |
| 资源与调度 | 自动伸缩 / 副本数、GPU 型号、容忍 | 自动伸缩默认开启，由 LLMScaler 在上下限之间管理副本数 |
| 路由 | 发布路由、路由路径、SLO、TTFT / TPS 阈值、ServiceMonitor | 控制请求如何进入推理实例，以及路由的服务目标和 Prometheus 采集配置 |
| 高级 | 覆盖 YAML | 一般不需要修改 |

多数字段留空即可，沿用站点配置和 chart 的默认值。

## 3. 预览并确认

点 **生成计划** 后进入预览：

- **部署计划**：这次部署由哪些配置层组合而成。
- **变更差异**：与集群现状相比将要改变的内容。
- **变更说明**：写下这次变更的原因，会记入操作记录。

确认无误后点 **确认部署**。

## 4. 等待就绪

在 [推理服务](/inferences) 列表查看状态：

| 状态 | 含义 |
|---|---|
| 部署中 | helm 正在执行 |
| 加载中 | Pod 已调度，正在读取模型权重 |
| 运行中 | 可以提供服务 |
| 失败 | 部署失败，到操作记录里看输出 |
| 未就绪 | 超过 1 小时仍未就绪，超出正常加载时间，需要排查 |

> **冷启动需要 20–40 分钟。** 大模型首次加载权重很慢，「加载中」通常不是出错。

点服务名进入详情，**概览**页按步骤展示进度：已应用 → 实例就绪 → 已接入路由 → 弹性伸缩。其他标签页：

| 标签 | 内容 |
|---|---|
| 实例 | Pod 列表、所在节点、重启次数 |
| 日志 | 按 Pod、容器查看最近日志 |
| 事件 | Kubernetes 事件，可只看告警（默认只保留 1 小时） |
| 版本管理 | 历史版本，可查看当时的 values 并回滚 |
| 操作记录 | 这个服务的部署、升级、回滚记录 |
| 部署计划 | 当前计划的组成 |

## 升级、回滚与卸载

在推理服务列表的行操作或详情页顶部操作：

- **升级**：修改模型版本、变体或设置，同样先预览差异再确认。服务名和命名空间不能改。**高级 → 覆盖 YAML** 会载入当前 Helm 修订的完整 values，可直接修改参数；只把有语义变化的项作为高级覆盖提交，不会因展示整份配置而固定所有旧默认值。已有高级覆盖会保留，数组按整项替换，删除的键以 `null` 提交。读取失败可重试；修订已变化时请关闭面板再重新打开。
- **回滚**：在「版本管理」里选一个历史版本，原样恢复当时的计划。要改设置请用升级。
- **编辑 SLO**：调整扩缩容依据的延迟、吞吐目标和副本数上下限。部署时没开 SLO 的服务需要先在升级时打开。
- **卸载**：停止服务并删除 Pod，操作记录保留。重新安装需要重新加载权重。

列表上的「落后目录」表示目录里有更新的版本，可以升级；「未纳管」表示这个 release 不是通过 swiss 部署的，不能在这里升级。

## 编辑目录中的变体

catalog-server 目录可以在模型详情页直接编辑。在 [站点配置](/inferences/site-profile) 的编辑器中把该目录勾选为 **可写**，并填入 catalog-server 的 **写入令牌**；令牌由 swissd 保存在它自己的 Secret 中。之后修改该目录除 **默认** 之外的任何设置（URL、名称、取消勾选 **可写**）都会移除令牌：修改时请重新输入。保存时会先向 catalog-server 校验令牌（新添加的目录也一样）：令牌不被接受或无法连接时，不会保存任何内容，编辑器会说明原因。每次修改都是目录的一次提交。

| 操作 | 入口 | 注意 |
|---|---|---|
| 初始化空目录 | 模型库工具栏的 **初始化目录** | 填写目录的发布地址和仓库；初始化之前无法添加模型 |
| 目录设置 | 模型库工具栏的 **目录设置** | 它的 `catalog.yaml`：`site`、`raw`、`repo` |
| 新增模型 | 模型库工具栏的 **新增模型** | 填写模型名和第一个变体 id、`metadata.yaml`，以及以目录中已有变体为副本的第一个变体 |
| 编辑模型 | 模型详情页头的 **编辑模型** | 它的 `metadata.yaml`：描述、默认变体、调优结果 |
| 新增变体 | 页头的 **新增变体** | 以默认变体为副本、版本 1.0.0 起步；修改其中的 `id`，它同时是文件名 |
| 编辑 | 变体卡片的 `⋯` 菜单 | 每次修改都要提升 `version`（可点 **升级版本号**）；**校验** 只检查不提交 |
| 删除 | 变体卡片的 `⋯` 菜单 | 默认变体、被调优结果引用的变体、模型的最后一个变体不能删除；历史记录会保留 |

- 可写目录在模型库的目录选择器中带有 **可编辑** 标记。
- 如果打开后文件已被他人修改，保存时会提示；重新加载后再编辑。
- 提交的作者是令牌的所有者，而不是当前用户。
- 如果令牌之后在 catalog-server 上被修改或移除，下一次修改时会提示；在站点配置编辑器中填入新令牌即可。
- 编辑需要模型部署后端（`swiss`）的权限：`update` 用于新增或修改变体、设置令牌，`delete` 用于删除变体或令牌。

## 节点与操作记录

- [节点](/inferences/nodes)：集群的 GPU 库存——空闲 GPU、单节点最大空位、各型号分布，以及不可用的节点。部署前可以在这里确认资源是否足够。
- [操作记录](/inferences/runs)：swissd 执行过的每一次部署、升级、回滚、卸载，展开一行可以看完整输出。

## 只读模式

如果操作按钮是灰色的，并提示「这个 swissd 是只读的」，说明集群上的 swissd 没有开启部署权限，只能查看。需要由运维在 swiss 的配置里打开 `allowDeploy`。
